# Contributing to ĀRU Intelligence Public Research

Thank you for approaching this work with technical curiosity and critical care.

## Useful contributions

- Reproducible bug reports
- Tests and validation harnesses
- Documentation corrections
- Accessibility improvements
- Performance measurements
- Independent replications
- Clear counterexamples
- Security disclosures
- Carefully scoped implementation proposals

## Before proposing a change

1. Read the target repository's README and license.
2. Search existing issues and pull requests.
3. Identify whether your contribution concerns implementation, simulation, observation, hypothesis, or metaphor.
4. Keep claims proportional to the evidence.
5. Avoid bundling unrelated changes.

## Bug reports

Include:

- Repository and commit or version
- Operating system and runtime version
- Exact reproduction steps
- Expected and actual behavior
- Minimal input or seed
- Relevant logs, screenshots, or output
- Whether the problem reproduces consistently

## Pull requests

A strong pull request explains the problem, the proposed solution, verification performed, limitations, and any documentation affected. Add tests when behavior changes. Do not silently alter authorship, licensing, research claims, or safety boundaries.

## Research discussion

Challenges and skeptical analysis are welcome. Be precise about what a result does and does not demonstrate. Symbolic terms used by a prototype should not be treated as empirical proof of consciousness or physical law.

## Conduct

Participate respectfully. Critique ideas and implementations rather than people. Harassment, threats, discrimination, doxxing, or deliberate disruption are not acceptable.

## Security

Do not publish exploitable security details in a public issue. Contact [office@aruintelligence.com](mailto:office@aruintelligence.com) with the repository name, impact, reproduction details, and a safe method for follow-up.
